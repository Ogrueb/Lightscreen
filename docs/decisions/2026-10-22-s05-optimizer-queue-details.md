# 2026-10-22 (Stage 6, S05): details of the PNG optimization queue and the bundled optimizers

Follows the plan's S05 and `2026-10-21-optipng-and-oxipng-both-selectable.md`; these are the choices those left open.

- **One queue, one process.** `Optimizer` (`tools/optimizer.{h,cpp}`) is owned by `ScreenshotManager`. Files run one at a time in the order added. The plan allowed two at a time; one keeps a burst from competing with the capture, and oxipng already uses every core for its one file.
- **The screenshot waits for its own file.** `Screenshot::optimize()` now only emits `optimizeRequested(fileName)`. The manager queues the file and calls the screenshot's `optimizationDone()` (upload or `finished`, as before) when `Optimizer::optimizationDone` reports that file, through a one-shot connection. So two screenshots that save to the same name (replace mode) each go on once.
- **Pending list.** `optimize-pending.txt` in the data directory (next to `history.sqlite`; the application directory in portable mode), one path per line, rewritten with `QSaveFile` whenever the queue changes and removed when it empties. A file stays listed while it runs, so a crash or a quit mid-run leaves it pending. Stopping the app kills the running tool and removes its temporary file. `LightscreenWindow` calls `resume()` once the event loop runs; files that no longer exist are skipped.
- **Tool choice.** As decided: `options/optimizer` (`oxipng` or `optipng`), absent means automatic (oxipng if found, else optipng), a missing chosen tool falls back to the other one, and the key is written only after the user picks in the combo box (or when it was already stored). The tool is resolved again for each file, so a change in the options applies to the next file in the queue.
- **Status.** The window title and tray tooltip show "N optimizing" when nothing uploads; uploads keep priority, as they did over "processing".
- **Bundled versions.** The owner supplied local copies of `oxipng.exe` 10.2.1 and `optipng.exe` 7.9.1 (OptiPNG's 2025 numbering; the decision named 0.7.8). Their SHA-256 hashes are pinned in `.github/scripts/fetch-optimizers.ps1`. The script downloads the upstream release archives, and the build fails unless each extracted exe matches its hash. This cloud environment cannot reach GitHub release or SourceForge downloads, so the URLs are first checked by CI. Each tool's licence files from its archive go into `licenses\<tool>\` in the deploy folder and the release zip.
- **Linux CI** installs optipng from apt and oxipng 10.2.1 with `cargo install --locked` (the binary is cached), so `tst_optimizer`'s `realTool` cases run both real tools.
- **Rejected.** A `QThreadPool` worker (a process per file needs no thread); `QSettings` for the pending list (a list of paths does not belong in the user's settings, and portable mode would put it in `config.ini`); building oxipng from source on Windows (a Rust toolchain on the runner for no gain).
