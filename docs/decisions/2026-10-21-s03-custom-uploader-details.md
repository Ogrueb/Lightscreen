# S03: details of the custom uploader the plan left open

- **Every service name reaches the custom uploader.** `Uploader::serviceName` returns `"custom"` for every index and `ImageUploader::factory` builds a `CustomUploader` for any name, including `"pomf"` and `"imgur"` from older settings. This keeps the M12 answer to bug 21 (never a null uploader). The service combo box keeps one entry, now "Custom", and `upload/service` keeps its meaning.
- **Where the migration runs.** `CustomUploader::migrateSettings(QSettings *)` runs in the `CustomUploader` constructor (so the first upload after the update already uses it) and at the start of the upload part of `OptionsDialog::loadSettings` (so the dialog shows the migrated values even before any upload). "`upload/custom/url` is not set" means the key is absent: once the dialog has saved, the key exists, so a URL the user cleared on purpose is not refilled from the old pomf URL. Trailing slashes on the pomf URL are dropped before `/upload.php` is added (the pomf uploader sent `//upload.php` in that case). The old `upload/pomf/*` keys stay, as the plan says. Rejected: running it once in `ScreenshotManager` at startup (the dialog tests build the settings after the manager, and a second call site is still needed for them).
- **URLs.** The URL goes through `QUrl::fromUserInput`, as the pomf URL did, so a migrated URL without a scheme still works (`http://` is assumed). Anything that does not end up `http` or `https` is refused before a request is made.
- **Order of the response checks.** Cancelled (`OperationCanceledError`) → `CancelError` with no message, which `Uploader` does not report (bug 22). Then an HTTP status outside 200-299 → "Upload failed: HTTP <status>", even when the body is JSON with a link (the pomf uploader ignored the status when the body parsed; the plan's spec says 2xx). Then any other network error → "Error reaching uploader: <Qt's message>". Then the body must parse as JSON → otherwise "Invalid response from uploader: <parse error>". Then the link path must give a non-empty string → otherwise "No link in the response: <why>". A pomf host's `description` on failure is no longer shown: it is pomf-specific and the generic message says where the link was looked for.
- **Paths.** Segments separated by dots; on an array a segment must be a non-negative integer in range, on an object it is a member name (so `"0"` works as an object key too); surrounding spaces are ignored. A path that does not resolve for the delete link gives an empty delete link, not an error, since the delete link is optional.
- **Headers.** One `Name: value` per line, split at the first colon, both sides trimmed; a line with no colon or no name is skipped silently. They are stored as one multi-line string under `upload/custom/headers` (QSettings escapes the line breaks in the INI file). The headers can hold a token; they are stored in plain text like every other setting (the Imgur token was too).
- **"Test upload" uses the form, not the saved settings.** The widget builds its own `CustomUploader` with `setUploaderSettings(<form values>)` and the app's network manager, posts a 1x1 transparent PNG from a temporary file, and shows the link (clickable) or the error. It does not go through `Uploader`, so a test upload never reaches the history, the tray or the clipboard. Closing the dialog during a test cancels it.
- **No host list**, as the plan says: the form starts empty except for the defaults `files[]` and `files.0.url`, shown as text in the fields so they are visible and saved.
