# S01: the area dialog is run by the main window, not by `ScreenshotManager`

- **`LightscreenWindow::selectArea` runs `AreaDialog`, not `ScreenshotManager`.** The plan put the dialog in `ScreenshotManager`, but the manager lives in `tools/` too, so including `dialogs/areadialog.h` there would break the very rule S01 adds. The manager stays the signal hub: it forwards each screenshot's `areaSelectionNeeded()` as `areaSelection(Screenshot *)`, and the main window answers it the same way it already answers `confirm(Screenshot *)` with the preview dialog. Rejected: moving `ScreenshotManager` out of `tools/` (a much larger change, and S02 reworks its ownership anyway).
- **The dialog stays modal (`exec()`), as before.** The selection still happens inside `Screenshot::take()`, so the order of signals and the nested event loop are the same as upstream. Rejected for now: a non-modal dialog, which would change what happens when another screenshot is requested while the selection is open.
- **F5 (refresh) goes through a signal.** `AreaDialog` no longer holds the `Screenshot`, so it emits `refreshRequested()`; the main window calls `Screenshot::refresh()` and hands the new desktop back with `AreaDialog::setPixmap()`. The connection is direct, so the refresh happens while the dialog is hidden, as before.
- **The autoclose option is still read from the settings in `AreaDialog`** (`options/areaAutoclose` through `ScreenshotManager::instance()->settings()`). `dialogs/` may include `tools/`, and the setting is not part of `Screenshot::Options`. S02, which removes the singleton lookups, can pass it in.
- **The include-graph check has only the first rule for now** (`tools/` includes nothing from `dialogs/` or `widgets/`). The second rule (`tools/uploader/` includes only itself and Qt) fails today on `tools/screenshotmanager.h` and `tools/os.h`; S02 removes those includes and adds the rule, as its done-check says. The check runs in the CI "Docs layout" job, which needs no build.
- **No screenshot is left waiting if nobody answers.** A `Screenshot` in area mode now waits for `setArea()` or `discard()`, like the window picker. In the app the main window always answers; a `ScreenshotManager` used without a window (tests) must answer itself or not take area screenshots.
