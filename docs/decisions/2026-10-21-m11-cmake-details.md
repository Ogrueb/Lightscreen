# M11: details of the CMake build the plan left open

- **Qt 6.2 stays the minimum, so no `qt_standard_project_setup()`.** It needs Qt 6.3. AUTOMOC/AUTOUIC/AUTORCC and C++17 are set by hand instead, which is all it would do here. Rejected: raising the minimum to 6.3 (no reason beyond one call).
- **Vendored libraries are `STATIC`, the app's sources an `OBJECT` library.** Static libraries keep the vendored code a self-contained unit with its own usage requirements (UGlobalHotkey's `UGLOBALHOTKEY_NOEXPORT` and `xcb` libraries). `lightscreen_core` must be `OBJECT` because it holds the Qt resources (`lightscreen.qrc`): from a static library they would need `Q_INIT_RESOURCE`. The uic output directory of `lightscreen_core` is a public include directory, since the headers include their `ui_*.h` and the tests include the headers.
- **Ninja on every preset, `cl` named explicitly on Windows.** One generator means one build-tree layout (`build/<preset>/`, no per-configuration subdirectory), which the smokes, the deploy step and the docs rely on. Naming `cl` keeps CMake from picking a MinGW `g++` that happens to be on `PATH` (the GitHub runner has one). The Windows preset therefore runs from a `vcvars64` prompt, as the qmake build did.
- **Windows version information written out.** qmake generated a `VERSIONINFO` resource from `VERSION` and `QMAKE_TARGET_*`; `cmake/lightscreen.rc.in` reproduces the same fields (company, description, file and product version 2.5.0.0, copyright, original file name, product name) and the icon. The strings live in the root `CMakeLists.txt`, next to `UPDATE_REPO`, so the rename (M16) edits one file.
- **One configure builds app and tests**, with `BUILD_TESTING` (default on) to leave the tests out. Rejected: a separate test project as with qmake's `tests/tests.pro`, which compiled the sources once per test.
