# 2026-10-20: M09, which Qt 6, and Qt 5's DPI rounding kept

- **Qt version.** CI installs Qt 6.8.3 (the LTS the plan names; the newest 6.8 patch release `aqtinstall` offered on 2026-10-20, pinned so runs are reproducible) with `jurplel/install-qt-action` on both runners, `win64_msvc2022_64` and `linux_gcc_64`. The Linux job no longer uses apt's Qt, so both platforms build against the same version. `src.pri` stops qmake with an error below Qt 6.2 (the first version with `QNativeInterface::QX11Application`, which M08 relies on); Qt 5 is not supported any more, although the `QT_VERSION` branches M07 and M08 added stay until M10 removes them. Ubuntu 24.04's Qt 6.4 still builds the app and passes the tests, so `docs/build.md` keeps it as the easy local route.
- **High DPI.** `Qt::AA_EnableHighDpiScaling` is gone in Qt 6 (scaling is always on). Qt 6 also changes the default scale-factor rounding from `Round` to `PassThrough`, so at 125% or 150% the logical coordinate system would no longer match what Qt 5 gave the capture, area-selection and window-picker code. `main.cpp` sets `Qt::HighDpiScaleFactorRoundingPolicy::Round` before the application object exists, which keeps Qt 5's geometry. Fractional scaling and per-screen DPI belong to S04 (bugs 4, 12, 23), which should revisit this line.
- **Rejected:** keeping the code building on both Qt 5 and Qt 6 for one more step. The few Qt 6-only calls M09 needs (`QKeyCombination`, `QMouseEvent::position()`, `qintptr` native-event results) would each need a new `QT_VERSION` branch that M10 deletes right after, and CI would only exercise one side.
- **Rejected:** `PassThrough` (Qt 6's default) now. It would change capture geometry on scaled displays in a step meant to be mechanical.
