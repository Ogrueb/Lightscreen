# S02: the uploader is owned by the manager and reached through it

- **`ScreenshotManager::uploader()` replaces `Uploader::instance()`.** The plan allowed `Uploader::instance()` to stay as a thin accessor on the manager, but forwarding it to the manager would need `tools/uploader/uploader.cpp` to include `tools/screenshotmanager.h`, which the new include rule forbids. The window, the history dialog, the options dialog and the pomf options widget call `ScreenshotManager::instance()->uploader()` instead (they already include the manager). Rejected: keeping a static `Uploader *` that the manager registers (a second singleton with no owner of its own, which is what S02 removes).
- **The network manager travels with the uploader.** `ImageUploader` gets the settings and the network manager in its constructor (through `factory`), so `PomfUploader` no longer looks up `Uploader::network()`. `PomfUploader::verify` is static and is used before any upload exists, so it takes the network manager as an argument. `Updater` takes it in its constructor, as the plan says; the app passes the uploader's, so there is still one `QNetworkAccessManager` for the app.
- **`connectScreenshot()` is public.** `take()` uses it, and tests that build a `Screenshot` directly use it to get the history rows that the old singleton call wrote. Rejected: making `take()` accept a ready `Screenshot` (it would also connect `finished` to `deleteLater`, which breaks the tests' stack screenshots).
- **The manager's default constructor no longer delegates to the test constructor.** The uploader needs the settings pointer when it is built, and the default constructor only knows it after choosing between `config.ini` and the user settings. Both constructors set their fields and then call a private `init()` that builds the uploader and connects `Uploader::done`.
- **Nothing in the behaviour changes.** The signals are emitted exactly where the calls were, connections are direct, and there is still one uploader and one network manager per run. The PR is still the owner's to merge (structural step, plan says "Merges: owner").
