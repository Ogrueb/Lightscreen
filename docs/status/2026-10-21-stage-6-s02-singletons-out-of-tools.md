# 2026-10-21: Stage 6, S02 done (singletons out of `tools/`)

- `Screenshot` no longer calls `ScreenshotManager::instance()` or `Uploader::instance()`. It emits `saved(fileName)` where it used to write the history row and `uploadRequested(fileName, service)` where it used to call the uploader, at the same points in `save()` and `upload()`. `ScreenshotManager::connectScreenshot()` wires both (to `saveHistory` and `Uploader::upload`, direct connections, so the order of history, upload and `finished` is unchanged); `take()` calls it for every screenshot.
- `Uploader` is owned by `ScreenshotManager`, built with the manager's `QSettings *`, and reached through `ScreenshotManager::uploader()`. `Uploader::instance()`, `setInstance()` and the static `network()` are gone; `network()` is now a member. `ImageUploader::loadSettings`/`saveSettings` take a `QSettings *`; `ImageUploader::factory` and the `PomfUploader` constructor take the settings and the network manager; `PomfUploader::verify` takes the network manager. `Updater` takes its network manager in the constructor (the window and the options dialog pass the uploader's). Details and rejected alternatives: `docs/decisions/2026-10-21-s02-uploader-owned-by-the-manager.md`.
- Include graph: nothing under `tools/uploader/` includes anything outside it but Qt and the standard library (`tools/os.h` and `tools/screenshotmanager.h` removed), and `updater/` no longer includes `tools/uploader/`. `tests/check-includes.sh` has the second rule; run against master it reports the three old includes, against this branch it passes.
- Tests: setup code only, no expected value changed. Tests that installed their own `Uploader` now use the manager's (`mManager->uploader()`); `tst_screenshot` calls `connectScreenshot` on the screenshots it builds itself (that is what still writes the history rows it checks); `tst_updater` passes its stub to the `Updater` constructor; `tst_uploader` passes settings and network to `factory`, `loadSettings`, `saveSettings` and `PomfProbe`. `tst_smoke::seams` checks that the manager owns the uploader. New `tst_uploader::screenshotUploadFlow`: a `Screenshot` with file and upload on, wired by the manager, with the stub network, ends with one `Uploader::done` and one history row carrying the URL.
- Not done here: `AreaDialog` still reads `options/areaAutoclose` through `ScreenshotManager::instance()->settings()`, and the dialogs and the window still reach the manager through `ScreenshotManager::instance()`. The plan only asks for `tools/` to stop using the singletons; `dialogs/` may include `tools/`.
- Local check (Ubuntu 24.04, apt Qt 6.4): app and tests build, all 11 suites pass under Xvfb, the CI Linux smoke passes, and a `--screen` capture with history on writes the PNG and one history row (the `saved` signal path in the app). CI: see the PR.
- Windows QA: `docs/windows-qa/2026-10-21-upload-after-s02.md`.
