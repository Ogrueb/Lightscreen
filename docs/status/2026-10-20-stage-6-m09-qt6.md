# 2026-10-20: Stage 6, M09 done (the Qt 6 flip)

- The app and the tests build with Qt 6 and C++17 only (`CONFIG += c++17`, `QT_DISABLE_DEPRECATED_BEFORE=0x060000`, qmake error below Qt 6.2). CI builds both platforms with Qt 6.8 from `aqtinstall`; the Linux job gained the xcb runtime libraries aqt's Qt needs. `docs/build.md` and the README describe the Qt 6 toolchain.
- Code changes, each forced by Qt 6:
  - `widgets/hotkeywidget.cpp`: the hotkey is built from `QKeyCombination(modifiers, key)`.
  - `tools/UGlobalHotkey/ukeysequence.cpp`: `QKeySequence::operator[]` returns a `QKeyCombination`; take `.key()`.
  - `lightscreenwindow.cpp`: `#include <QActionGroup>` (moved to its own header in Qt 6).
  - `nativeEvent` takes `qintptr *` in `OptionsDialog` (Print Screen in the hotkey field) and `UGlobalHotkeys` (`WM_HOTKEY`, i.e. every global hotkey on Windows), now marked `override`. With the old `long *` signature both still compiled on Qt 6 but were never called.
  - `QMouseEvent::pos()` / `globalX()` / `globalY()` became `position().toPoint()` / `globalPosition().toPoint()` in the area dialog, preview dialog and window picker (left here by M04).
  - `tools/os.cpp` (Windows cursor capture): `QBitmap::fromPixmap` instead of the removed `QBitmap(QPixmap)` constructor. M07's Qt 6 branch of `os::pixmapFromHBITMAP(bitmap, true)` reinterpreted `QImage::fromHBITMAP`'s result as premultiplied ARGB, but that function makes every pixel opaque, so `tst_os` failed on Windows and a captured cursor would have had an opaque box; the alpha case now reads the pixels with `GetDIBits`.
  - CI: the Windows job reruns each test with its output in a file and prints it when the tests fail, because `nmake check` shows no test output there.
  - `dialogs/areadialog.cpp`: Qt 6 changed `QRect::normalized()`: for an inverted rectangle it now moves each swapped edge in by one pixel, so a selection dragged up or to the left would have been two pixels smaller than on Qt 5. The safety-net test `tst_AreaDialog::updateHandles(inverted)` caught it. The dialog now calls a local `normalizedRect()` with Qt 5's semantics at its seven call sites; no test changed.
  - `tests/tst_history`: `QStandardPaths::DataLocation` (removed) became `AppLocalDataLocation`, the same value and what the app has used since M04, so the test still checks that the history file does not move.
  - `tests/tst_uploader` (`uploadDone`): Qt 6.7 and later write multipart header names in lower case (`content-disposition:`), which HTTP treats the same; the test now compares header names case-insensitively. Header values and the upload itself are unchanged.
  - `main.cpp`: `AA_EnableHighDpiScaling` (gone in Qt 6) replaced by the `Round` scale-factor policy, so geometry on scaled displays stays as on Qt 5. Why: `docs/decisions/2026-10-20-m09-qt-6-version-and-dpi-rounding.md`.
- Nothing needed for `QSqlQuery`: positional `addBindValue` behaves the same, and `tst_history` passes.
- Local check (Ubuntu 24.04, apt Qt 6.4): app builds, all 11 test suites pass under Xvfb (331 test functions and rows). CI (Qt 6.8): see PR #42.
- Windows QA, the long pass from the plan: `docs/windows-qa/2026-10-20-qt6-flip.md`. The owner merges (plan: "Merges: owner").
- Left for M10: the `QT_VERSION` branches from M07/M08 and in `tst_mainwindow`, `qAsConst` (deprecated since 6.6, warns on 6.8). Also deprecated after 6.0 and still compiling with a warning: the `QMessageBox::question` overload with button texts in `lightscreenwindow.cpp`, and `QSqlDatabase::exec`.
