# 2026-10-21: Stage 6, S03 done (user-configurable uploader replaces pomf)

- `tools/uploader/pomfuploader.*` became `tools/uploader/customuploader.*` (`CustomUploader`) and `widgets/pomfoptionswidget.*` became `widgets/uploaderoptionswidget.*` (`UploaderOptionsWidget`), both renamed with `git mv` and rewritten. Settings under `upload/custom/`: `url`, `field` (default `files[]`), `headers` (one `Name: value` per line), `linkPath` (default `files.0.url`), `deletePath` (optional). Request: multipart `POST` of the file under `field` with the extra headers. Response: HTTP 2xx and the link path gives a non-empty string → `uploaded(file, link, deleteLink)`; anything else → `error` with the HTTP status or a parse/path message. `Uploader::serviceName` returns `"custom"` and the factory builds a `CustomUploader` for every name. Details: `docs/decisions/2026-10-21-s03-custom-uploader-details.md`.
- **Migration.** If `upload/pomf/pomf_url` is set and `upload/custom/url` is absent, `url = pomf_url + "/upload.php"`, `field = files[]`, `linkPath = files.0.url`; the old keys stay. Runs in the `CustomUploader` constructor and in `OptionsDialog::loadSettings`.
- **Options dialog.** The upload tab's service box has one entry, "Custom"; below it the five fields and "Test upload", which posts a 1x1 PNG with the values in the form (saved or not) and shows the link or the error. "Verify" (pomf only) is gone.
- **Bug 22 fixed:** cancelling an upload no longer reports an error (`OperationCanceledError` → `CancelError`). Bug 21 stays fixed (unknown name → `CustomUploader` → "No upload URL set").
- **Tests, expected values changed on purpose** (safety-net changes, listed in the PR): `tst_uploader` (service name and factory class are now `custom`/`CustomUploader`; the pomf response rows became custom-uploader rows; `cancel` now expects no error, bug 22; error texts "No upload URL set" / "Invalid upload URL" replace "Invalid pomf uploader URL!"); `tst_settings` (`defaults.golden` and `roundtrip.golden` have the five `upload/custom/*` keys instead of `upload/pomf/pomf_url`; the window's `uploadService` is `custom`; the legacy settings test checks the migration); `tst_mainwindow` (`--uploadlast` error text). New tests: request field and headers, link and delete paths incl. arrays and missing keys, HTTP 500/404, non-JSON, empty link, network error, `resolvePath` table, the migration table, an upload with only old pomf settings, the options widget's "Test upload" (success, error, cancel), and multi-line headers through the INI file.
- Local check (Ubuntu 24.04, apt Qt 6.4): app and tests build, all 11 suites pass under Xvfb, `tests/check-includes.sh` passes (`tools/uploader/` still includes only itself and Qt). CI: see the PR.
- Not done: no real upload from the cloud (no host to trust). Manual check for the owner: `docs/windows-qa/2026-10-21-custom-uploader.md`.
