# 2026-10-22: Stage 6, S05 done (PNG optimization queue, oxipng and optipng)

- **New `tools/optimizer.{h,cpp}`** (`Optimizer`, owned by `ScreenshotManager`): a FIFO of files, one process at a time, the tool writing to `<file>.optimize.tmp` that replaces the original only on exit code 0, `optimizationDone(fileName)` exactly once per file (also when no tool is found, the file is gone, or the process does not start), the pending list in `optimize-pending.txt` next to the history, resumed at startup. `Screenshot::optimize()` now only asks for the file to be queued; its process code and `replaceFile` moved to the optimizer.
- **Tool choice** as decided in `docs/decisions/2026-10-21-optipng-and-oxipng-both-selectable.md`: `options/optimizer`, automatic when absent (oxipng, else optipng), silent fallback to the other tool. Options dialog: a combo box next to "Optimize PNG screenshots" with "oxipng" and "OptiPNG", each marked "(not found)" when missing; the checkbox is disabled only when neither is found ("Install oxipng or OptiPNG" on Linux, "No optimizer found next to lightscreen.exe" on Windows).
- **Status:** the window title and tray tooltip show "N optimizing".
- **Windows zip:** `.github/scripts/fetch-optimizers.ps1` adds `oxipng.exe` 10.2.1 and `optipng.exe` 7.9.1 with their licence files, from upstream archives checked against SHA-256 hashes of the owner's own copies; used by the CI deploy step and by the release workflow. The download URLs were not reachable from the cloud container; CI is their first check.
- **Linux CI** installs optipng (apt) and oxipng 10.2.1 (`cargo install`, cached) for the real-tool tests.
- **Tests, changed on purpose (safety net):** `tests/tst_optimize` became `tests/tst_optimizer` and `tests/optipng_stub` became `tests/optimizer_stub` (built as both `oxipng` and `optipng`; logs start and end of each run; new modes "hang" and a sleep). The five old cases (success, stale temporary, failure keeps the original, no output keeps the original, missing binary) now run against the optimizer and against both tools. New: missing file, a burst of five run one at a time in order, a hanging run still pending after a restart and then optimized, resume with nothing pending, the choice and fallback table, the screenshot flow through the manager (two screenshots on one file each finish once), and both real tools on a real PNG (pixels unchanged, file not larger). `tst_settings`: the second-save expectation now turns `options/optimize` off only when neither tool is found (was: when optipng is not); new `dialogOptimizerChoice` (absent key stays absent, a picked tool is saved, a stored one is kept). Golden files unchanged.
- **Local check** (Ubuntu 24.04, apt Qt 6.4, optipng 0.7.8 and oxipng 10.2.1 installed): app and tests build, all 12 suites pass under Xvfb, `realTool` passes for both tools; include-graph and docs checks pass.
- **Bugs:** 10 fixed in code (queue, bound, persistence, tray count; its Stage 5 part was already done), awaiting `docs/windows-qa/2026-10-22-png-optimizers.md`. Bug 20 (PNG quality forced to 80) unchanged: S05 does not make compression configurable.
