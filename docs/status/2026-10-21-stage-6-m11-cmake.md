# 2026-10-21: Stage 6, M11 done (CMake replaces qmake)

- New: root `CMakeLists.txt`, `tests/CMakeLists.txt`, `tools/SingleApplication/CMakeLists.txt`, `tools/UGlobalHotkey/CMakeLists.txt`, `CMakePresets.json` (`linux-release`, `linux-debug`, `windows-msvc-release`; Ninja, build trees under `build/<preset>/`) and `cmake/lightscreen.rc.in`. Deleted in the same PR: `lightscreen.pro`, `src.pri`, `version.pri`, `tests/tests.pro`, `tests/common.pri`, every `tests/*/*.pro`, `tools/SingleApplication/singleapplication.pri`, the four `tools/UGlobalHotkey/*.pri` and `uglobalhotkey.pro`.
- Layout as the plan asked: `lightscreen_core` is an `OBJECT` library with everything but `main.cpp`; the app and each test link it. SingleApplication and UGlobalHotkey are `STATIC` libraries (no source change; both `VENDORED.md` files record it). Each test still builds into its own directory, and `optipng_stub` still lands in `tst_optimize/stub/`.
- Kept from qmake: C++17, `QT_DEPRECATED_WARNINGS` and `QT_DISABLE_DEPRECATED_BEFORE=0x060000`, `APP_VERSION` (now from `project(VERSION 2.5)`), `UPDATE_REPO` (now `LIGHTSCREEN_UPDATE_REPO` in the root `CMakeLists.txt`), the Windows and X11/xcb libraries, `/utf-8` (qmake's `CODECFORSRC`), the WIN32 subsystem, the icon and the version information in the exe (written out in the `.rc` template since qmake generated it), `/MANIFESTUAC:level='asInvoker'`. Qt 6.2 stays the minimum (`find_package(Qt6 6.2 ...)`); `qt_standard_project_setup()` is not used because it needs 6.3, so AUTOMOC/AUTOUIC/AUTORCC are set by hand.
- CI: both jobs run `cmake --preset`, `cmake --build --preset`, `ctest --preset` (Linux under `xvfb-run -a`, Windows with `QT_QPA_PLATFORM=offscreen` from the test preset). The smokes run from `build/linux-release`; the Windows deploy copies `build\windows-msvc-release\lightscreen.exe` and runs `windeployqt` as before, artifact still `lightscreen-win64`. The "Show test output (on failure)" step is gone: ctest prints a failing test's output itself.
- Comments and docs that named `version.pri` now name `CMakeLists.txt` (`updater/updater.{h,cpp}`, `tests/tst_updater/tst_updater.cpp`, `docs/goals.md`); `CLAUDE.md` says Qt 6 / CMake; `docs/build.md` and `README.md` describe the CMake build. `.gitignore` drops the qmake patterns and ignores `CMakeUserPresets.json`.
- Done-check, local (Ubuntu 24.04, apt Qt 6.4, CMake 3.28): `linux-release` and `linux-debug` build; all 11 test suites pass under Xvfb with ctest; both smokes pass from `build/linux-release`. CI (Qt 6.8, both platforms): see PR #44.
- Windows QA: `docs/windows-qa/2026-10-21-cmake-build.md` (the owner's one-time build with the preset, plus exe icon and file properties).
